# Error

Request Blocking (403)

# Root Cause

Issue identified, project was using old code base, even in new we're using session based proxy whose health was poor.

# Fix

Migrated to new code base, switched from session based proxy to rotating proxy.

# Debugging Process

1. Check Code structure.
1. Found code was in legacy.
1. Referenced BCBS MT, BCBS MN, Sapphire module to migrate to new code base.
1. Still the same issue, so checked the host settings/env variable as well as config.yaml file
1. Found out we're using session based proxy.
1. Check if base module support proxy injection or not.
1. Found Sapphire module had hardcoded proxy set.
1. Fixed the Sapphire module to accept proxy via yaml then via env then fallback to default session based method.
1. Added dataimpulse\_rotating to config.yaml
1. Did test runs, all valid

This also should solve the issue of false drop NPIs not being scraped for the healthsparq sites for orgs with multiple NPIs.

# Key Takeaway

This fix should also be applicable for all sapphire projects. Since this was project specific issue, the first thing after migration is to check whether we're using appropriate proxy or not. Session based proxy would not be ideal for every scenarios.
