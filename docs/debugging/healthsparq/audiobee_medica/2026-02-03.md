# AutoQA not pulling all data

## Error

AutoQA not pulling all data

## Root Cause

The issue lies with how networks list is used. The search for NPI is conducted across all networks, even if the provider did not have the network listed in previous runs. Currently, AutoQA first uses an NPI search followed by a label search. When the NPI search yields no results, it defaults to a label search, which can return data even without a match. This results in the incorrect provider being mapped to the AutoQA result.

## Fix

1. Use NPI only autoQA (quick) + Name only AutoQA
2. Update the healthsparq/ package to use network specific search (Future improvement)

## Debugging Process

1. **Cache Investigation**: Checked the recovered.db to check the missing provider data
2. **Data Verification**: Found that while the file existed, the data was for another provider
3. **Isolation Testing**: Moved the cache to temp and ran only for the missing provider - still the same error
4. **Code Flow Analysis**: Traced the code flow for provider with networks and found that the cache and provider data was pulled from 0th index of the network list of the full list even though the provider was not present in the network
5. **Search Logic Issue**: Found that the NPI returned empty data but then the label search resulting in providers being found which was not the target provider
6. **Solution Validation**: Deduced that the label search could be the cause of error and by running NPI only search, the missing provider was accurately scraped

## Key Takeaway

When AutoQA combines NPI and label searches, the fallback label search can return incorrect matches when NPI searches fail. For healthsparq sites, separating NPI-only and name-only AutoQA processes provides more accurate results. Future improvements should implement network-specific searches to prevent cross-network data pollution.
