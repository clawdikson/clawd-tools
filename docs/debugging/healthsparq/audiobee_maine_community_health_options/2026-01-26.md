# Error

False NPI drop

# Root Cause

Identified the cause to be the label (name) search after the initial NPI search only showed names (label) instead of ids. This resulted in name search due to which the provider but with different NPIs were pulled.

# Fix

Intermediate search function between NPI and keyword search using the search results api with additional params.

# Debugging Process

1. Checked auto QA files to confirm the issue was with scraping, not mapping.
1. Found intermediate search by NPI/name data missing in raw cache. Updated code to store this in raw files (DB).
1. Reran auto QA with updated cache and identified providerId mismatch for keyword search returning names (labels) instead of IDs after initial NPI search.
1. Replicated NPI search in UI and identified that a different api (search results, phase 1) was used with fallback parameters when only labels were returned.
1. Added an intermediate search function between NPI and keyword search using the search results api with additional params.
1. Reran auto QA, confirming the fix resolved the issue.

This also should solve the issue of false drop NPIs not being scraped for the healthsparq sites for orgs with multiple NPIs.
